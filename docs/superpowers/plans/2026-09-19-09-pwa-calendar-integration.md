# LeihNest PWA and Calendar Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make LeihNest installable as a safe PWA and add standards-based iCalendar export/feed for reservations without caching private authenticated data offline.

**Architecture:** Use Next.js metadata/manifest plus a deliberately minimal service worker. Cache only static/public shell assets and an offline page; never cache authenticated HTML/API responses. Calendar export is server-generated from authorized reservation data. Personal feed tokens are random, hashed at rest, revocable, and expose only the owning user's reservation data.

**Tech Stack:** Next.js 16, React 19, Prisma 7, PostgreSQL 17, Web App Manifest, Service Worker, RFC 5545 iCalendar, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-19-leihnest-product-completion-design.md`

## Global Constraints

- No offline mutations.
- Service worker never caches `/app/*`, `/api/*`, `/invite/*`, `/i/*`, auth callbacks, media, billing, or calendar token feeds.
- Calendar tokens are not session tokens and cannot access any non-calendar data.
- Personal feed shows only the token owner's reservations.
- Feed tokens are stored hashed, not raw.
- PWA remains fully usable as normal browser app when install APIs are unavailable.

## Review Focus

1. Private workspace response never lands in Cache Storage.
2. Revoked calendar token immediately stops serving calendar data.
3. ICS escaping handles commas, semicolons, backslashes, and newlines.
4. Deleted/removed member feed returns 404 after token invalidation.
5. Install UI does not trap users when browser lacks install prompt support.
